The Core Guided Code Tour Route

Follow one complete verification cycle through the actual codebase:

Stop 1: Deterministic Boundary Derivation & Approval Gate
src/shared/ruleEngine.ts → generateBoundaryTestCases()
src/server/storage/planStore.ts → createPlan() & approvePlan()

The rule engine mathematically derives exact boundary cases (threshold - 1, threshold, threshold + 1) and demonstration probes. The server records an immutable TestPlanRecord with isApproved: false until the user explicitly confirms the plan snapshot via POST /api/plans/:id/approve.

Stop 2: Independent Black-Box Form Observation
src/server/runner/formObserver.ts → observeFormSubmission()
src/server/runner/browserPool.ts → createHermeticContext()

Playwright launches an isolated Chromium browser context with network route interception restricting all requests strictly to 127.0.0.1. The observer enters the value, clicks submit, and races DOM status indicators ([data-testid="status-accepted"] vs [data-testid="field-error"]) without reading internal form threshold variables.

Stop 3: Discrepancy Classification & Atomic Checkpointing
src/shared/ruleEngine.ts → compareOutcomes()
src/server/storage/runStore.ts → saveActiveCheckpoint() & reconcileStartupCrashes()

The comparator compares the policy expectation with the observed form outcome, categorizing the test into one of four mutually exclusive classifications (CONSISTENT, CONFIRMED_MISMATCH, INCONCLUSIVE, EXECUTION_ERROR). Inconclusive and unrelated errors can never produce a false mismatch claim. Active runs write atomic .active-[runId].json progress files to survive sudden process restarts.

Stop 4: Self-Contained Offline Evidence Generation
src/server/report/reportGenerator.ts → generateHtmlEvidenceReport()

Serializes the immutable snapshot, strict HTML-escaped DOM feedback, and base64-encoded screenshot captures into a single, offline HTML file with zero external script or style dependencies.

To Change This, Start Here

Modify Workbench Visual Theme & Colors src/client/styles/tokens.css (Workshop + Gridline design tokens).

A Practice to Reuse

Genuine Black-Box Observability & Sampling Disclaimers

Software verifiers must never inspect internal form validation variables to confirm agreement, as internal code can harbor the exact bug being investigated. By restricting the verifier strictly to user-observable DOM outcomes (accessibility roles, status indicators, and feedback messages), verification remains independent and authoritative. Additionally, pairing finite boundary samples with honest discrepancy language (“inconsistencies confirmed at tested values between X and Y”) avoids the dangerous false premise of claiming universal form correctness from a finite set of tests.
